# Стартовый промпт для реализации фичи «Поддержка Windows»

Скопируй целиком и вставь в новую сессию.

---

Реализуй фичу **Поддержка Windows** по подготовленной документации.

## Документация

- Спецификация: `docs/features/windows-support/spec.md` — прочитай перед началом
- План: `docs/features/windows-support/plan.md` — следуй порядку задач, секции «Стратегия выполнения» и «Ревью после каждого шага»
- Чеклист: `docs/features/windows-support/checklist.md` — отмечай прогресс
- Предварительный анализ: `docs/plans/windows.md` — детальный разбор каждой проблемы с примерами кода (используй как референс)

## Инструкции

1. Прочитай `spec.md`, `plan.md` и `checklist.md` целиком.
2. Создай ветку `feature/windows-support` от `main` и переключись на неё: `git checkout -b feature/windows-support`.
3. Отметь в checklist.md пункты «Подготовка» как выполненные.
4. Выполняй задачи согласно **стратегии выполнения** и зависимостям в plan.md:
   - `sequential` — строго по порядку.
   - `parallel-subagent` — можно вынести параллельным субагентам после выполнения зависимостей.
   - `parallel-same` — параллельно в одной сессии.
5. После **каждой** задачи: ревью по plan.md и spec.md; убедись, что нет конфликта с параллельными задачами (общие файлы, противоречивая логика). Если задачу делал субагент — проверь результат перед следующим шагом.
6. После выполнения задачи — отметь её в checklist.md (`[x]`).
7. Запусти указанную для задачи проверку (`npm run build` или `npm test`).
8. Коммить после каждого блока задач.
9. По завершении — отметь «Финализация» в checklist.md и обнови статус в README.md на `Done`.
10. Если что-то непонятно — спроси, не додумывай.

## Ключевые решения (уже согласованы)

- **Symlinks на Windows:** стратегия fallback: `symlink('dir')` → junction → копирование.
- **Agent Launcher:** `.bat` файлы для cmd.exe (не .ps1).
- **Утилита `platform.ts`:** единый хелпер вместо inline `process.platform`.
- **Тестирование:** unit-тесты с моком `process.platform` (без windows-latest CI runner).
- **Новая зависимость `cross-spawn`:** не добавляем.

## Поле «Базовая ветка для merge»

Базовая ветка: `main`. Не меняй без причины — по нему скилл feature-accept подставляет цель слияния.
