# Стартовый промпт для реализации фичи «Загрузка расширений в каталог»

Скопируй целиком и вставь в новую сессию.

---

Реализуй фичу **Загрузка расширений в каталог** по подготовленной документации.

## Документация

- Спецификация: `docs/features/catalog-upload/spec.md` — прочитай перед началом
- План: `docs/features/catalog-upload/plan.md` — следуй порядку задач, секции «Стратегия выполнения» и «Ревью после каждого шага»
- Чеклист: `docs/features/catalog-upload/checklist.md` — отмечай прогресс

## Инструкции

1. Прочитай spec.md, plan.md и checklist.md целиком.
2. Создай ветку `feature/catalog-upload` от текущей и переключись на неё.
3. Отметь в checklist.md пункты «Подготовка» как выполненные.
4. Выполняй задачи согласно **стратегии выполнения** и зависимостям в plan.md:
   - `sequential` — строго по порядку.
   - `parallel-subagent` — задачи #11, #12, #13 можно вынести параллельным субагентам после выполнения задачи #10.
5. После **каждой** задачи:
   - Сверка с plan.md и spec.md (скоуп, критерии приёмки).
   - Убедись, что нет конфликта с параллельными задачами (общие файлы, противоречивая логика).
   - Если задачу делал субагент — проверь результат перед следующим шагом.
6. После выполнения задачи — отметь её в checklist.md (`[x]`).
7. Запусти указанную для задачи проверку.
8. Коммить после каждого логического блока задач (блок 1, блок 2, блок 3, блок 4).
9. По завершении — отметь «Финализация» в checklist.md и обнови статус в README.md на `Done`.
10. Если что-то непонятно — спроси, не додумывай.

## Ключевые технические детали

- **Git-операции:** используй `simple-git` (уже в зависимостях) — см. `cli/src/git.ts` как образец.
- **Проверка доступа:** `git push --dry-run` к URL каталога (`registryUrl` из конфига). Кешируй результат в React state (хук `useUploadAccess`).
- **Валидация:** наличие файла, фронтматтер (name, description, version, author), уникальность в catalog.json, kebab-case.
- **Upload flow:** создать ветку → скопировать файлы → обновить catalog.json → commit → push → вернуть main → показать URL PR.
- **URL PR:** детект платформы по URL (github.com, gitlab.com, fallback), параметры title + body.
- **TUI:** UploadScreen — pushed screen (аналог DetailScreen/MoveScreen). Паттерны: `useInput` + `normalizeInput`, `Box`/`Text` из Ink.
- **Точки входа:** ExtensionSyncDialog (hotkey `u`), InstalledDetailScreen (действие), InstalledScreen (hotkey `u`). Все скрыты если `hasAccess === false`.
- **Батч:** все выбранные расширения в один commit + один PR.
- **После push:** `git checkout main` чтобы не сломать кеш каталога для остального CLI.
