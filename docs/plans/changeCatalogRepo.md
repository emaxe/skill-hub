# Очистка расширений при смене репозитория каталога

## Проблема

При смене `registryUrl` (через CLI `config set` или TUI Settings) текущий код:
1. Удаляет кеш каталога (`~/.skill-hub/`) через `resetCache()`
2. **Не трогает** записи расширений в `.skill-hub.json`
3. **Не трогает** записи в `installed.json`
4. **Не трогает** файлы расширений на диске

В результате после смены каталога:
- `.skill-hub.json` ссылается на расширения, которых нет в новом каталоге
- `installed.json` содержит устаревшие записи
- На диске остаются файлы-призраки расширений
- `sync.ts` показывает ошибки — расширения помечаются как `missing` или `untracked`

## Решение

При смене `registryUrl` — очищать записи о расширениях **только из проектного конфига** (`.skill-hub.json`), с предупреждением пользователю. Файлы расширений на диске и `installed.json` **не трогать** — они продолжат работать как есть.

## Затрагиваемые файлы

| Файл | Что менять |
|------|------------|
| `cli/src/git.ts` | Расширить `resetCache()` — добавить очистку проектного конфига |
| `cli/src/commands/config.ts` | Предупреждение + подтверждение при `config set registryUrl` |
| `cli/src/tui/screens/SettingsScreen.tsx` | Предупреждение в TUI при смене URL (2 места) |

## Детальный план

### 1. Создать функцию `fullCatalogReset()` в `git.ts`

Центральная функция, вызываемая из всех мест смены URL. Логика:

```
fullCatalogReset():
  1. Если есть проектный конфиг (.skill-hub.json) и в нём есть extensions:
     - Очистить extensions[] → saveProjectExtensions([])
  2. Удалить кеш каталога (текущий resetCache())
```

Файлы расширений на диске и `installed.json` **не трогать**.

**Важно:** `resetCache()` остаётся как есть для внутреннего использования (например, в `ensureCache()`). Новая `fullCatalogReset()` — надстройка для смены URL.

### 2. Предупреждение в CLI (`commands/config.ts`)

При `skill-hub config set registryUrl <url>`:

```
⚠  Смена каталога приведёт к очистке списка расширений в .skill-hub.json:
   • 2 расширения в проекте /path/to/project

   Файлы расширений на диске останутся без изменений.

   Продолжить? (y/N)
```

- Показать количество расширений из `.skill-hub.json`
- Если расширений нет — не показывать предупреждение
- Запросить подтверждение через `readline` (или `inquirer`)
- При отказе — не менять URL
- Флаг `--force` / `--yes` для пропуска подтверждения (для скриптов)

### 3. Предупреждение в TUI (`SettingsScreen.tsx`)

При изменении `registryUrl` в TUI — показать модальное окно подтверждения:

```
┌─────────────────────────────────────────────┐
│  ⚠  Смена каталога                          │
│                                             │
│  Список расширений в .skill-hub.json (5 шт.) │
│  будет очищен. Файлы на диске останутся.     │
│                                             │
│  [Продолжить]    [Отмена]                   │
└─────────────────────────────────────────────┘
```

Два места вызова `resetCache()` в `SettingsScreen.tsx` заменить на:
1. Открытие `ConfirmModal` с предупреждением (если есть расширения в конфиге)
2. При подтверждении — вызов `fullCatalogReset()`
3. При отмене — откат значения `registryUrl`

### 4. Автодетект в `ensureCache()` (git.ts)

Сейчас `ensureCache()` сам определяет смену origin и вызывает `resetCache()`. Нужно:
- Заменить на `fullCatalogReset()` 
- Или оставить только `resetCache()` (кеш), т.к. предупреждение уже было показано при смене URL через config/TUI

**Рекомендация:** оставить `resetCache()` в `ensureCache()` — это fallback на случай ручной правки конфига. Расширения уже должны быть очищены на этапе config set / TUI.

## Граничные случаи

| Случай | Поведение |
|--------|-----------|
| Нет установленных расширений | Сменить URL без предупреждения (нечего удалять) |
| Расширения только в global scope | Не затрагиваются (очищается только `.skill-hub.json`) |
| Расширения в нескольких проектах | Очищается `.skill-hub.json` только текущего проекта |
| URL меняется на тот же URL | Не запускать очистку (уже проверяется `urlChanged`) |
| `--force` флаг (CLI) | Пропустить подтверждение, выполнить очистку |
| Ошибка при очистке конфига | Вывести warning, продолжить сброс кеша |
| `.skill-hub.json` нет в проекте | Пропустить очистку, только сбросить кеш |

## Порядок реализации

1. `git.ts` — функция `fullCatalogReset()`
2. `commands/config.ts` — предупреждение + подтверждение
3. `SettingsScreen.tsx` — модальное подтверждение (2 места)
4. Тесты
