# Выход из режима agents-conventions

Полная подготовка рутовой папки проекта к работе без конвенции
[agents-conventions](../agents-conventions/SKILL.md): миграция скиллов и правил обратно
в формат целевого агента, обратная сборка корневых файлов, очистка артефактов конвенции.

## Цель

Полностью вывести проект из режима `agents-conventions`:
- Собрать корневые файлы ИИ-агентов (`CLAUDE.md`, `.cursorrules`, `.github/copilot-instructions.md`) из `.agents/rules/`
- Перенести пользовательские скиллы из `.agents/skills/` в директорию целевого агента
- Перенести правила из `.agents/rules/` в формат целевого агента
- Удалить тонкие указатели

Удаление симлинков, `AGENTS.md` и директории `.agents/` выполняет CLI автоматически.

Все операции идемпотентны: если артефакт уже удалён/мигрирован — пропустить.

## Подготовка

Перед началом определи целевой агент из сообщения запуска (например, "Target agent: claude-code").
Если целевой агент не указан — спроси пользователя.

## Алгоритм

### 1. Проверка текущей структуры

Убедись, что:
- Директория `.agents/` существует
- `AGENTS.md` существует в корне проекта

Если структура нарушена — сообщи об этом и предложи продолжить с тем, что есть.

### 2. Обратная сборка корневых файлов ИИ-агентов

Восстановить корневые файлы конфигурации из `.agents/rules/project-rules.md`.

#### Определение источника

Прочитать `.agents/rules/project-rules.md`. Файл может содержать:
- Секции с маркерами источника (`## Из CLAUDE.md`, `## Из .cursorrules`, `## Из .github/copilot-instructions.md`) — если был мигрирован при `init-agents`
- Единый контент без маркеров — если был сгенерирован автоанализом

#### Логика восстановления

**Если `project-rules.md` содержит маркеры источников:**

Для каждого маркера извлечь содержимое и записать в соответствующий корневой файл:

| Маркер | Целевой файл |
|---|---|
| `## Из CLAUDE.md` | `CLAUDE.md` (корень проекта) |
| `## Из .cursorrules` | `.cursorrules` |
| `## Из .github/copilot-instructions.md` | `.github/copilot-instructions.md` |

Восстанавливать только те файлы, маркеры которых присутствуют в `project-rules.md`.
Если целевой файл уже существует и НЕ является тонким указателем — пропустить.

**Если `project-rules.md` не содержит маркеров (автосгенерированный):**

Записать содержимое `project-rules.md` в корневой файл целевого агента:
- `claude-code` → `CLAUDE.md` (корень проекта)
- `cursor` → `.cursorrules`
- `copilot` → `.github/copilot-instructions.md`

Если целевой файл уже существует и НЕ является тонким указателем — пропустить.

**Если `.agents/rules/project-rules.md` не существует** — пропустить шаг.

### 3. Инвентаризация пользовательских скиллов

Найти все скиллы в `.agents/skills/` — это директории, содержащие `SKILL.md`.

Исключить bootstrap-скиллы:
- `agents-conventions`
- `init-agents`
- `exit-agents`

Пользовательские скиллы — все остальные.

### 4. Миграция скиллов в директорию целевого агента

Определи целевую директорию скиллов в зависимости от агента:
- `claude-code` → `.claude/skills/`
- `cursor` → `.cursor/skills/`
- `copilot` → `.github/skills/`

Создать целевую директорию если не существует.

Для каждого пользовательского скила:

```
если {target}/skills/{skill-name}/ НЕ существует:
    скопировать папку .agents/skills/{skill-name}/ в {target}/skills/{skill-name}/
иначе:
    пропустить (скил уже есть в целевой директории)
```

### 5. Миграция правил из .agents/rules/

Найти все `.md` файлы в `.agents/rules/`, кроме `project-rules.md` (обработан на шаге 2).

Определи целевой формат в зависимости от агента:

#### claude-code
Правила хранятся как обычные `.md` файлы в `.claude/`.
Для каждого правила из `.agents/rules/{name}.md`:
- Если `.claude/{name}.md` не существует — скопировать туда

#### cursor
Правила — файлы `.mdc` в `.cursor/rules/`.
Для каждого правила из `.agents/rules/{name}.md`:
- Создать `.cursor/rules/{name}.mdc` со стандартным frontmatter если не существует:

```
---
description: {описание из файла или имя файла}
alwaysApply: false
---
{содержимое правила}
```

#### copilot
Правила — файлы `.instructions.md` в `.github/instructions/`.
Для каждого правила из `.agents/rules/{name}.md`:
- Создать `.github/instructions/{name}.instructions.md` со стандартным frontmatter если не существует:

```
---
applyTo: "**"
---
{содержимое правила}
```

### 6. Обработка AGENTS.md

Прочитай `AGENTS.md`.

Если в `AGENTS.md` есть inline-правила (не только ссылки на файлы в `.agents/rules/`):
- Для `claude-code`: добавить их в `CLAUDE.md` (корень проекта) — дополнить к уже восстановленному содержимому
- Для `cursor`: добавить их в `.cursor/rules/project-rules.mdc`
- Для `copilot`: добавить их в `.github/instructions/project-rules.instructions.md`

Если `AGENTS.md` содержит только ссылки — ничего не делать, правила уже мигрированы.

### 7. Удаление тонких указателей

Удалить тонкие указатели, созданные при инициализации:

| Файл | Условие удаления |
|---|---|
| `.claude/CLAUDE.md` | Содержит только ссылку на `AGENTS.md` |
| `.cursor/rules/project-rules.mdc` | Содержит только ссылку на `AGENTS.md` |
| `.github/instructions/project-rules.instructions.md` | Содержит только ссылку на `AGENTS.md` |

Проверять содержимое перед удалением: если файл содержит пользовательский контент 
помимо ссылки на `AGENTS.md` — не удалять.

Также проверить и удалить тонкие указатели в корневых файлах (если они были заменены 
на шаге 2, корневой файл уже содержит восстановленный контент — тонкий указатель 
перезаписан):
- `CLAUDE.md` (корень) — если остался тонким указателем и не был восстановлен на шаге 2, удалить
- `.cursorrules` — аналогично
- `.github/copilot-instructions.md` — аналогично

### 8. Финальная проверка

Проверить что всё готово к передаче управления CLI:
- Все пользовательские скиллы скопированы в `{target}/skills/`
- Все правила скопированы в формат целевого агента
- Корневые файлы восстановлены (если применимо)
- `.agents/` НЕ удалена (это сделает CLI)
- Симлинки НЕ удалены (это сделает CLI)
- `AGENTS.md` НЕ удалён (это сделает CLI)

Вывести краткий отчёт:
- Сколько скиллов мигрировано и куда
- Сколько правил мигрировано и в каком формате
- Какие корневые файлы восстановлены
- Что было пропущено и почему

## Ограничения

Скилл выполняет миграцию пользовательского контента и очистку тонких указателей.
Структурную очистку (удаление симлинков, `AGENTS.md` и директории `.agents/`)
выполняет CLI автоматически после завершения этого скилла.

## Использование

Скилл вызывается автоматически при переключении агента с `agents-conventions` на
другой агент через TUI или CLI. Можно также запустить вручную для проверки готовности
к выходу из режима.
